# 0.8.1 registry-free lifecycle contract

**Trust:** The trusted component catalogue remains a filter, not proof of signed authorship. Discover valid identities and exact versions without executing code. Use component source manifests first, verified legacy inference when allowed, never a folder name alone; report contradictions and block managed actions. The configured Components root is the only managed ownership boundary. External executables and launchers are not adopted, run, rewritten or removed automatically.

**State:** Filesystem discovery establishes real runtime/Recovery availability. One exact Suite-authored `.desktop` entry is authoritative for normal active runtime if its metadata and actual `Exec` target match an installed validated runtime. If absent, fall back to remembered preferences and offer Repair; if broken, external or missing required Suite metadata, stop normal launch and file routing and ask for explicit repair. If the valid entry disagrees with remembered preferences, ask before synchronizing the fallback. If neither is available, ask the user to choose an installed version/runtime. Manual newly discovered components may be managed by virtue of being inside the root but receive a once-per-session activation offer; declining does not record an ownership/dismissal database.

**Formats:** Installing a trusted ZIP creates a Portable and retains an exact Recovery ZIP and original SHA checksum. Installing a provided AppImage creates an AppImage runtime. Both are ordinary desktop-integrated, activatable first-class runtimes. Build/Rebuild AppImage from existing Portable is Developer Mode only and independent of desktop state, not part of ordinary ZIP installation. Future AppImage-to-Portable extraction is out of scope. Independent normal active-vs-desktop selection is Advanced/Developer behaviour. A valid existing AppImage launcher is not converted to Portable. Reinstall of the same exact version warns, stages only its relevant runtime, and couples ZIP Portable with its matching Recovery original, preserving parallel AppImage.

**Recovery:** Remove Portable preserves Recovery. Normal Restore Portable always offers explicit Activate/Integrate (default No when another runtime works). A mismatch against a retained ZIP's recorded checksum may be overridden only after an explicit warning; archive structure/path safety, trusted ID, exact version, race detection and runtime validation remain mandatory. A corrupt/unreadable ZIP cannot be restored. Never silently rewrite integrity metadata to match altered bytes.

**Removal:** Preview and transactionally stage complete version-folder removal (Portable+AppImage+Recovery), reject unexpected entries at the version root and symlinks. If active, explicitly offer replacement runtime/version or verified launcher removal; never knowingly strand a launcher. Purge covers every version, a verified managed launcher and component-specific preferences, but preserves catalogue-level routing capabilities and global Hub OS associations. External files are never touched. If desktop integration fails after successful installation, keep the installed runtime, preserve the previous selection/launcher, label partial success and offer Repair.

**Retirement:** The prior central `managed-registry.json` is unlinked unconditionally and never read for normal discovery. The obsolete `managed_installations` preferences key is dropped. No backup, replacement central database or installation ownership manifest is introduced. AppImage/Recovery sidecars continue to provide identity/provenance and integrity information only, without mirroring desktop ownership.
