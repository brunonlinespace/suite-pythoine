# Suite Pythoine 0.3.0 — component and routing recovery audit

0.3.0 deliberately recovers the last confirmed-good 0.2.4 routing lifecycle and then reapplies later UI/packaging improvements behind a centralized component policy.

The critical invariant is that Linux OS-handler capability and internal Editor capability are different. Suite Pythoine is a Hub that may receive the Editor MIME union from the OS, but `hub` and `extension` components are excluded from document candidate selection. All pre-GUI and GUI routing paths use the same policy.

The release gate must reproduce the former regression condition by installing Suite itself beside all current Editors under a fresh configuration. Unambiguous files must launch their sole Editor with no chooser and no full Hub construction. Genuine ambiguity must produce only the compact chooser.

0.3.0 also establishes the new `~/Suite Pythoine/` component root, role-aware Details, explicit routing preferences, automatic Make Active desktop synchronization, independent runtime preference, the optional verified external component catalogue, and the hardened non-privileged packaging/source-cleanliness contract.
